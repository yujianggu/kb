# 共用汇报模板

本目录位于项目根目录，供不同公司和业务主题共用。两份模板按汇报侧重点选择，内容均以汇报主题组织。产品经理、技术研发、数据工程师共同围绕场景提供材料，不分别形成岗位工作总结；事项表中记录负责人和协作方即可。

| 模板 | 适用场景 | 核心关注 |
|---|---|---|
| [侧重业务](侧重业务-汇报模板.md) | 业务规划、成效复盘、推广与资源决策 | 问题与目标、整体方案、业务结果、风险和决策 |
| [侧重技术](侧重技术-汇报模板.md) | 方案评审、交付验证、运行复盘、技术演进 | 业务约束、架构取舍、系统与数据协同、验证、运行质量和决策 |

## 使用方法

1. 先明确本次听众需要作出的判断，再选择一个主模板，按主题收集证据。
2. 在所属项目或公司业务的汇报目录下建立主题目录，将模板复制为该主题正文；模板本身不填写具体项目进展。
3. 按需要裁剪章节和表格，不适用的维度不强行填充；规划阶段写验证计划，复盘阶段写实测结果。
4. 同一主题同时面向业务与技术汇报时，可形成两种视角，但共用同一套指标、状态和证据，避免重复维护不一致的事实。
5. 较长资料放在主题附件或关联文档；发布文件按所属项目的目录和版本保留规则组织。

## 共通要求

- 结论与诉求在前，正文围绕主题串联业务、系统、数据和运营。
- 目标、计划、实际交付和已验证效果分开表述，不能以某个角色完成工作替代整体结果。
- 指标说明范围、周期、基准和来源；原因区分事实与假设。
- 后续行动明确负责人、协作方、时间和验收依据；决策说明备选、代价及未决影响。
