# AI 大模型知识库方案对比与选型

查阅日期：2026-10-12。本页是对十家提供方案及 LLM Wiki 模式的**研究归纳与选型建议**，证据和细节以链接的案例正文及来源页为准。未进行统一部署或基准测试；“优先评估”不等于实测胜出。

## 先明确要购买或自建的环节

一个完整候选方案需要说明：资料来源 → 解析 → 切片 → 嵌入与索引 → 授权后的检索 → 重排与上下文组织 → 大模型回答 → 证据展示 → 更新、删除与评测。

不同产品负责的范围不同。检索数据库、RAG 框架、应用平台和云托管知识库不能直接按“都有知识库”视作同类替代品；使用组件时，要列出仍由团队承担的环节。

| 构建方式 | 对应案例 | 优先评估的情况 | 需要自己验证或承担的工作 |
|---|---|---|---|
| 云托管知识库／RAG 服务 | [阿里云百炼](阿里巴巴/README.md)、[AWS](AWS/README.md)、[Google Cloud](Google-Cloud/README.md) | 已有云环境，希望减少知识库基础设施集成 | 来源治理、地域、连接器、权限语义、更新与费用；各服务覆盖范围有差别 |
| 云检索服务作为 RAG 底座 | [Microsoft](Microsoft/README.md) | 希望在 Azure 环境组织检索并接入大模型应用 | 解析／索引配置、应用生成链路、实际权限和功能可用性 |
| RAG 应用平台／引擎 | [Dify](Dify/README.md)、[RAGFlow](RAGFlow/README.md) | 需要可配置的问答流程，或验证文档处理路线 | 部署运维、模型／存储依赖、权限、许可和端到端效果 |
| 检索底座 | [Elastic](Elastic/README.md)、[Pinecone](Pinecone/README.md)、[Weaviate](Weaviate/README.md) | 需要控制检索结构，或已有检索基础设施 | 数据处理、索引同步、授权过滤、模型编排和评测；托管选项并不免除应用职责 |
| 数据接入与 RAG 编排框架 | [LlamaIndex](LlamaIndex/README.md) | 希望以代码控制数据管线与检索流程 | 模型、存储、部署、观测、权限及工程维护；框架能力与关联云服务分开核验 |
| 持续知识整理模式 | [Karpathy LLM Wiki](Andrej-Karpathy/README.md) | 跨资料理解反复使用，需要积累项目上下文 | 来源与版本、整理错误、审查与更新；可叠加到检索架构上，不是同类托管服务 |

此分类仅说明本次研究的主要角色，提供方可能另有产品；不穷尽其产品线。

## 如何判断“最佳”

以下是本库建议的比较方法，指标须在本方语料上测量，不采用厂商宣称直接打分。

| 比较项 | 验证问题 |
|---|---|
| 数据与解析 | 中文、扫描 PDF、表格、代码与图文是否保留关键结构？错误能否定位到原文？ |
| 检索质量 | 正确证据能否进入候选集？型号、编号、同义表达和跨文档问题表现如何？ |
| 回答可信度 | 回答是否有充分依据？引用是否真的支持结论？无答案时能否说明缺失？ |
| 权限与隔离 | 未授权内容是否在进入模型上下文前被排除？匿名、跨部门、跨租户是否分别验证？ |
| 维护与时效 | 更新、撤销和删除何时生效？旧索引、缓存与会话是否仍暴露过期资料？ |
| 部署与集成 | 目标地域、网络、连接器和数据出境要求是否满足？哪些组件需自己维护？ |
| 成本与迁移 | 解析、嵌入、存储、检索、重排和生成的费用如何累计？原文及索引元数据能否迁出？ |

不要将“回答看起来专业”视作质量指标，也不要以生成后的内容过滤代替检索前授权。

## 推荐评估顺序

1. **确定任务与边界**：先选一个业务用途，写明语料、用户、权限、更新频率和可接受延迟。
2. **建立小型真实测试集**：覆盖有答案、无答案、旧版本冲突、精确编号、复杂表格及越权请求。记录期望证据和判定准则。
3. **筛选两到三种候选**：先排除地域、许可及部署不匹配项，再比较覆盖范围和集成责任。
4. **先测检索，再测回答**：分别记录证据命中、回答依据、引用对应、拒答、延迟和单次成本，避免把召回问题归因于大模型。
5. **验证生命周期**：更新并删除测试文档，验证召回、回答、缓存与审计记录；验证失败重试及恢复。
6. **形成决策记录**：保留语料版本、产品配置、模型版本、测试结果和未解决项。结论限定于本次任务和测量条件。

## 对当前仓库的建设建议

本仓库目前是有稳定主题 ID、分层索引和来源边界的文档库，不是运行中的向量数据库。若后续接入 RAG，建议以正文与来源作为受控输入，保留主题 ID、文件路径、版本和适用限制作为可回查元数据。

`requires` 与 `related` 的原始含义应保留；切片不能割掉适用边界，也不能让 `reference` 或教学示例在回答中变成已核实事实。公司扩展继续显式准入。上述是后续接入建议，本次没有改变解析工具，也没有上传公司资料或创建外部服务。
