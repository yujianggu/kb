# Weaviate：混合检索与生成式查询知识库

## 提供方及定位

Weaviate 的数据库及模型集成为 AI 大模型知识库提供检索和生成式查询组件。本案例采用混合检索筛选知识片段，再结合生成模型回答问题的路线。它不是内容治理、源系统授权及业务门户全部齐备的整套方案；数据处理与应用责任需单独设计。研究依据是公开官方文档，不代表企业内部落地事实。

## 官方确认的能力

混合检索融合向量搜索与 BM25F 关键词搜索，支持调整融合方式和相对权重；alpha 为 1 时只使用向量，为 0 时只使用关键词。查询还可使用属性过滤和返回排名说明。[官方混合检索](https://docs.weaviate.io/weaviate/search/hybrid)

生成式查询先检索，再把结果及提示词交给配置的生成模型。可为每个对象生成结果，或把多条结果作为一组完成任务；可限制送入分组任务的属性。[官方 RAG 文档](https://docs.weaviate.io/weaviate/search/generative)

## 推荐构建流程（研究建议）

以下是组合已确认能力形成的设计建议，并非产品默认保障。

1. **确定数据对象。** 以知识片段为检索对象，保留正文、原文位置、文档 ID、版本与业务类别。记录来源及可见范围，明确哪些字段仅用于治理，哪些字段允许送入大模型。
2. **处理原始内容。** 自行选择解析与切分组件，核对扫描件、表格和标题结构。保持术语、编号、时间条件与正文关联，不把不完整的片段误当独立有效事实。
3. **建立查询基线。** 分别测试关键词、向量和混合检索。评测集包含具体产品编号、同义表达、多条件问题及无答案问题，判断哪类问题需要加强精确词匹配，哪类依赖语义。
4. **调节融合策略。** 明确设置权重而非依赖客户端默认值，记录排名说明与命中证据。按评测表现选择配置，不宣称混合检索对所有问题都优于单一路径。
5. **构造生成输入。** 选择需要的证据字段，限制上下文长度，保留可核对出处。问题需要综合多条知识时采用分组任务；答案生成后继续检查引用与关键结论是否被证据支持。
6. **建立生命周期。** 文档更新后替换片段，文档撤回时清理索引、缓存和衍生内容。模型、索引配置或数据改变后运行固定评测，并记录延迟、调用失败及证据缺失原因。

## 适用场景

适合同时存在精确编号与自然语言问题、需要透明调节检索策略、拥有数据库和应用工程能力的团队，可用于产品手册问答、技术支持和业务知识助手。若需要自动接管各源系统权限或开箱即用的企业知识门户，应进一步验证相应产品与集成，而不是仅依据生成式查询能力决定。

## 限制与治理

原生混合搜索与模型集成不能替代内容真实性审查。属性过滤可以限定查询，但字段值如何对应用户权限、谁能修改这些字段、撤权怎样生效，均需组织在应用侧明确。不能假设导入文件时原系统授权自动迁入。

生成模型必须配置并可调用，接入外部模型意味着检索片段可能离开数据库所在环境，应核实实际数据流向。建议只传递必要属性，不把内部治理字段默认放入提示词。来源返回与答案引用不是同一件事，应保留逐条证据核对机制。

官方示例随客户端和数据库版本变化，本案例不承诺所有版本支持相同参数。未实测中文分词、混合权重效果、长文解析、部署维护、性能或费用，不将检索分数解释为事实置信度。

## 可借鉴点

给精确匹配和语义理解各自保留检索通道，用可解释排名辅助诊断，再把生成步骤建立在可追溯证据上。将数据字段、访问规则与模型输入分开设计。
