# LlamaIndex：可组合数据接入与 RAG 编排

## 提供方及定位

LlamaIndex 提供面向大模型数据应用的开发框架。本案例聚焦 Python 框架的数据接入、索引、检索和响应合成，用于构建可定制的 AI 知识库。框架帮助连接各阶段，实际仍需选择存储、嵌入模型、生成模型和部署方式；本案例不将框架等同于整套托管知识库，也不将官方教学流程当作企业上线实绩。

## 官方确认的能力

官方将 RAG 分为加载、索引、存储、查询和评估阶段。Document 表示来源内容，Node 表示知识片段；检索器提供相关上下文，节点后处理可做过滤或重排，响应合成器根据问题和片段生成答案。[官方 RAG 概述](https://developers.llamaindex.ai/python/framework/understanding/rag/)

IngestionPipeline 可组合切分、抽取和嵌入等转换，返回节点或写入向量存储，并缓存节点与转换结果。连接文档存储后可按文档 ID 和内容哈希识别重复或变化，实际处理还取决于是否连接向量存储。[官方接入流水线](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)

## 推荐构建流程（研究建议）

以下方案需工程团队组合、部署与验证，不是框架自动提供的治理保证。

1. **先定义问答边界。** 选定业务资料、读者与允许回答的问题，建立包含出处的人工评测集。把无答案、知识冲突、资料过期和访问受限的情况纳入验收。
2. **统一来源身份。** 将文件或接口内容加载为文档，附来源地址、版本、时间、负责人和访问标签。文档 ID 必须跨多次导入保持稳定，否则重复检测与变更追踪无法可靠对齐。
3. **组合接入转换。** 先解析并检查格式，再选择切分和必要元数据抽取，最后生成嵌入。记录转换配置版本，避免缓存掩盖新配置或模型变化。复杂表格和扫描文档需选择并验证适用解析组件。
4. **配置存储与增量处理。** 明确文档存储、向量存储和缓存各保存什么。用新增、重复、内容变化和删除样本检查同步，不把去重机制理解为自动处理全部源系统生命周期。
5. **组合查询链。** 根据身份确定可搜索范围，然后使用检索器获取证据，必要时以节点后处理筛选或重排。响应合成时保留出处与位置，设置证据不足的回答策略；需要多步查询时先评估复杂度收益。
6. **拆开评估与上线。** 分别记录召回、证据排名、答案忠实度、引用和延迟。先验证有限数据集，再扩大来源范围；每次切分、模型或存储配置变化都运行回归，定位具体失败阶段。

## 适用场景

适合需要组合多个数据源、模型与检索策略，愿意以代码管理 AI 知识库的工程团队，也适合建立可替换组件的实验环境。若缺少部署和维护能力，需要单独评估托管产品，而不是直接将教程代码视为生产服务。LlamaCloud、LlamaParse 等产品不在本条目的能力核验范围内。

## 限制与治理

已确认的是框架抽象、接入转换、缓存和文档变化处理机制；源系统授权继承、用户身份、删除传播、提示注入防护和审核制度需自行设计或验证具体集成。缓存、向量库与会话中保留的数据要纳入撤权和删除流程。

模型与数据库分别存在调用失败、成本及配置约束，框架不自动消除这些依赖。应固定组件版本、保存配置和评测数据，核对外部模型接收哪些内容。不能因检索链完整就认为回答一定正确，也不能将一次问答演示视为可复现效果。

本案例未部署框架或运行代码，未核验连接器覆盖、中文效果及规模性能；官方文档的接口与链接可能变化，实施时应对照选定版本。

## 可借鉴点

将知识库拆成可测且可替换的阶段，使接入、存储、检索和生成失败能够分别定位。稳定文档身份、记录处理配置和按阶段评估，比堆叠复杂查询组件更容易形成持续维护的系统。
