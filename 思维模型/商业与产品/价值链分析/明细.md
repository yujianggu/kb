# 价值链分析：明细

> 内容类型：通用知识版。采用波特价值链概念；经营汇报方法为本库整理的应用扩展。未关联来源视频。

## 概念与分析单位

波特价值链以具有战略意义的活动为分析单位，考察企业的成本与差异化优势从何而来。分析范围通常选定一项业务；企业还处于供应商、渠道等构成的更大价值系统中。参考：[哈佛商学院战略与竞争力研究所：The Value Chain](https://www.isc.hbs.edu/strategy/business-strategy/Pages/the-value-chain.aspx)。

经典分类可作为检查清单：

| 活动类别 | 组成 | 阅读提示 |
|---|---|---|
| 基本活动 | 内部物流、生产运营、外部物流、市场营销与销售、服务 | 关注产品或服务的形成与交付；内部物流指投入物接收、仓储等，并非部门间信息流转 |
| 支持活动 | 企业基础设施、人力资源管理、技术开发、采购 | 为多项基本活动提供条件；采购还包括设备和服务，不只买原材料 |

分类依据：[HBS：What Is a Value Chain Analysis?](https://online.hbs.edu/blog/post/what-is-value-chain-analysis)。支持活动并非次要活动，也不等同于某几个职能部门。

战略分析还要检查活动是否相互强化：产品定位、设计方式、交付安排和服务承诺能否配合。单项活动高效，并不自动形成有区别的经营方式。参考：[HBS：Fit Across the Value Chain](https://www.isc.hbs.edu/strategy/creating-a-successful-strategy/Pages/fit-across-the-value-chain.aspx)。

## 与相近概念的区别

以下按本库的实际使用目的区分，三个视角可以共同使用。

| 视角 | 主要问题 | 常见输出 |
|---|---|---|
| 价值链分析 | 活动怎样影响成本与客户价值，怎样形成经营优势？ | 活动配置、连接关系、经营取舍 |
| 价值流分析 | 从需求到交付，哪里存在等待、返工和流动障碍？ | 流程现状、时间数据、改善方向 |
| 系统架构分析 | 系统、数据与接口怎样支撑业务？ | 系统职责与集成关系 |

“研发 → 供应商 → 生产 → 售后”可作为汽车质量的业务观察范围，但它是行业场景展开，不能称为波特经典五类基本活动。质量工作横跨多项活动；一套系统也可能同时支撑多个环节。

## 分析步骤：从业务事实走向经营选择

以下六步为本库整理的工作方法。

1. **界定服务对象。** 写明业务、客户、产品与周期。内部平台要同时识别直接使用者和最终业务受益者，解释两者如何连接。
2. **识别关键活动。** 从实际流程、资源投入与交付物整理活动；标注负责人和上下游。先写“维护质量策划、验证整改效果”等业务动作，再标注系统。
3. **收集价值与成本证据。** 核对客户反馈、处理量、等待时间、返工、费用及损失。统一周期、样本和统计范围；共享成本说明分摊方法。
4. **检查跨环节影响。** 找到一个活动如何改变另一个活动的工作量、质量或交付条件。对因果尚不清楚的关系列出假设及验证办法。
5. **比较方案。** 同时考虑收益、建设与持续运营投入、适用范围、依赖条件及风险。必要的质量控制不能仅因难以量化收益而取消。
6. **形成选择并验证。** 明确先做什么、负责人、试点范围、检查时间和调整条件。比较改善前后的同口径数据，并记录产量、产品结构等其他影响因素。

## 向上级汇报经营逻辑的六个问题

| 问题 | 汇报应给出的内容 | 质量平台的填写方向 |
|---|---|---|
| 为谁创造价值？ | 服务对象与业务需要 | 质量业务团队需要更早发现并处理风险，最终改善产品质量与客户体验 |
| 价值在哪里产生？ | 关键活动与损失位置 | 聚焦重复问题、晚发现问题或处理等待，说明影响范围 |
| 怎样产生价值？ | 活动改变到结果的机制 | 风险经验进入策划，形成保证活动并验证执行效果 |
| 需要投入什么？ | 总投入与必要条件 | 开发集成、业务运营、标准维护、数据治理和培训 |
| 如何证明有效？ | 过程指标、结果指标与验证设计 | 先看采用与执行，再看重复问题和损失；写明比较基准 |
| 为什么这样取舍？ | 推荐方案、备选方案和代价 | 优先选可验证的关键场景，明确扩展条件与本次决策事项 |

可将这六个问题写成一页材料，以[金字塔原理](../../表达与协作/金字塔原理/README.md)表达主张，以[OGSM](../../行动与复盘/OGSM目标管理工具/README.md)对齐目标，以[PDCA](../../行动与复盘/PDCA循环/README.md)跟踪结果。

## 投入产出与证据边界

以下为内部改善项目的测算提示，并非波特原模型的利润计算公式。

- 把收益拆为可核实的费用减少、释放的工作容量、业务损失改善及风险变化。释放工时尚未转化为费用减少时，不写成现金节省。
- 成本覆盖一次性建设与持续维护、运营、培训等投入；比较备选方案应采用相同周期。
- 同一批问题的返工费、质量损失和索赔回收可能重叠，需核对口径；损失降低与损失转移也应区分。
- 预测收益明确假设与范围，实际收益列明来源。时间先后关系不足以证明平台是唯一原因。
- 若需要跨年财务回报测算，再按企业财务口径处理现金流与折现；本模型不能独立给出投资结论。

## 常见误用

| 误用 | 改进方法 |
|---|---|
| 用部门组织图代替活动分析 | 列出活动、交付物与连接，允许一项活动跨部门完成 |
| 只追求本环节成本最低 | 检查全链条成本和客户体验是否恶化 |
| 把系统清单当成价值链 | 为每项系统能力补上业务行为变化与结果证据 |
| 将内部效率改善等同于竞争优势 | 继续说明是否影响客户价值、相对成本及活动配合 |
| 用完整的箭头图证明因果 | 对关键连接设置可观察指标与验证条件 |

与[波特五力模型](../波特五力模型/README.md)配合时，五力分析行业结构，价值链分析本业务如何组织活动。复杂跨组织生态或快速变化的业务，还需检查边界与合作关系，不能仅靠一张静态图。
