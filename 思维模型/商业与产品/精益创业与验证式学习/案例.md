# 精益创业与验证式学习｜教学案例

以下为本库编写的假设练习。客户、金额、样本、结果及门槛全部虚构，仅用于演示推理；不是市场均值、实际成交或推荐价格。

## 场景：月度资料追收服务

团队想为小型事务所提供客户资料追收工具。最初计划开发账号、消息提醒、文件上传和看板，但关键问题是：事务所是否愿意为减少追收工作付费，以及交付是否需要过多人工。

本轮决定：是否投入两周开发自助原型。先测试购买与交付，不试图在两周内证明长期留存。

### 实验计划（假设）

| 字段 | 事前约定 |
|---|---|
| 客户 | 经确认每月需向至少10个客户追收资料、且有采购决定权的小型事务所 |
| 样本 | 从一个行业社群接触30家机构，目标为10家符合条件且看到完整报价；不足则记为样本未达计划 |
| 交付 | 一次指定范围的资料清单整理与追收协作，由人工辅助；向客户明确说明能力与边界 |
| 报价 | 每家300元，仅覆盖本轮约定任务 |
| 学习目标 | 有人购买，且人工投入有下降空间 |
| 指标 | 完整报价送达数、实际付款数、完成交付数、退款、每单人工时间 |
| 继续门槛 | 10家有效报价样本中至少3家付款、至少3家完成验收，且完成订单平均直接人工不超过2小时、无退款 |
| 实验上限 | 两周，团队总投入不超过20小时；到期记录结果，不为凑够订单无限延期 |

门槛仅为本例的经营决策规则，无统计显著性含义；实际项目应根据资源和成本自行制定。

### 假设结果与计算

接触30家，12家符合条件，10家看到完整报价，3家付款，3家完成，无退款；每单平均直接人工3小时。实收900元，工具及支付等变动成本合计90元；假设直接人工每小时80元，共9小时。

- 付款／看到完整报价 = 3／10 = 30%。分母不是30家接触对象。
- 本轮交付贡献 = 900 − 90 − 9 × 80 = 90元，即每单30元。
- 若另有5小时获客工作，同样按80元计价，扣除此项后的金额为90 − 400 = −310元；仍未包括固定开发等成本。

30%的样本付款率不能直接外推整个市场；这个社群的成员与其他渠道客户可能不同。

### 学到了什么

购买门槛达到，交付人工门槛未达到，所以本轮没有满足投入自助原型的全部条件。能够支持的结论是：在这个社群、报价和人工服务条件下，3家机构购买并完成任务。尚不能支持软件自助使用、月度续费或规模化获客。

下一步可以先拆分3小时中的重复环节，提出“标准清单能减少重复整理时间”的新假设，用新的交付试验验证。是否提高价格是另一项购买假设，应记录新条件。不能删除获客人工后宣布已实现盈利。

## 反例：实验未执行好，不等于没有需求

假设第二轮联系20家机构，仅2家实际收到报价，其余消息未送达；最终无人付款。0／20混合了渠道失败和购买行为，应分别记录送达率及0／2的付款情况。结果不足以判断需求不存在，先确认渠道可达性，再决定是否值得继续测试。

## 练习

如果三笔订单均来自创始人的熟人，推论应如何缩小？如果交付期从两周延长到一个月，实验版本和观察期限如何记录？如果省掉人工后客户无法完成任务，哪条假设需要重测？

检查自己的回答是否明确了样本、条件和未知项，而不只是换一个更乐观的结论。
